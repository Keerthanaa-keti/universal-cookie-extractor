Cookie Vault v3 — Roadmap

Zero-knowledge, per-server scoped access to your browser cookies on remote servers
LIVE — Phases 0–7 shipped 24 tests + 7 live checks green Kiket EC2 reading Updated 2026-08-18

TL;DR

The old vault put your password and a master decryption key on every server — one breach meant total account takeover and every cookie exposed. v3 replaces that with a zero-knowledge, least-privilege design: each server holds only its own private key and a scoped, revocable token; the database and broker never see cookie plaintext.

LIVE as of 2026-08-18. New free Supabase project cookie-vault (us-east-2) created, schema applied, broker deployed, and your Kiket EC2 server is reading cookies through it — decrypting locally with a key that never left the box. One step remains for real data: configure the extension in Chrome so your real cookies sync.

Your one remaining step

The vault currently holds only a test cookie. To sync your real cookies, load the extension and configure it:

  1. Load the unpacked extension (chrome://extensions → Developer mode → Load unpacked → this repo).
  2. Options → Connection: paste the Project URL + anon key, sign in with the owner account, set a vault passphrase, enable sync. Values are in ~/.cookie-vault/SETUP.txt.
  3. Options → Servers already lists kiket-ec2 (or click Rewrap now). Your real cookies then flow to Kiket automatically.
